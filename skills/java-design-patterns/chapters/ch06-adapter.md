# Chapter 6: 适配器模式

## Core Idea
把既有接口转换为调用方需要的契约，让不兼容组件协作，同时把外部变化限制在边界层。

## Frameworks Introduced
- **Adapter**：转换协议、字段、错误和调用语义。
  - When to use：第三方 API、遗留系统、不同 MQ 消息或不同版本接口需要统一接入。
  - How：定义领域端口 → 每个外部系统一个适配器 → 显式完成映射与错误翻译。

## Key Concepts
- **端口与适配器**：领域接口是端口，基础设施实现是适配器。
- **反腐层**：阻止外部模型和术语污染内部领域。

## Modern Java
适配器可返回 record 作为稳定数据载体；映射必须处理未知字段、空值、版本演进和失败语义，不能只改方法名。

## Worked Example
原书把不同 MQ 消息中的用户编号抽取为统一字段，并统一自营与第三方订单的首单查询接口。调用方只传统一参数，不再知道消息或订单来源。

## Anti-patterns
- 在领域对象上添加所有供应商字段。
- 捕获异常后统一返回 `null`。
- 一个“万能适配器”处理几十种协议。

## Key Takeaways
1. 适配器应位于系统边界。
2. 同时转换数据、行为和错误语义。
3. 每个外部变化源独立适配。
