# Chapter 11: 享元模式

## Core Idea
把大量对象中可共享的内在状态与每次调用的外在状态分开，以共享不可变对象降低内存和创建成本。

## Frameworks Introduced
- **Flyweight**：通过键查找并复用共享实例。
  - When to use：对象数量巨大、重复状态占主要内存，且共享收益已被测量。
  - How：识别不可变内在状态 → 外在状态作为参数传入 → 有界缓存管理实例。

## Worked Example
原书缓存秒杀活动的静态信息，同时让库存从独立存储更新。活动描述可共享，实时库存不能被错误地固化在享元中。

## Modern Java
字符串池、包装类缓存和缓存库都体现共享思想。生产系统应使用有界、可过期、可观测缓存，避免手写无界 `ConcurrentHashMap`。

## Anti-patterns
- 共享可变对象却没有并发策略。
- 缓存键包含高基数请求数据，导致内存泄漏。
- 未测量内存瓶颈就引入复杂缓存。

## Key Takeaways
1. 只共享不可变或受控状态。
2. 外在状态由调用方提供。
3. 缓存必须定义容量、失效和监控。
