# Chapter 13: 责任链模式

## Core Idea
让请求沿有序处理器传播，每个节点决定处理、修改、继续或终止，发送者无需知道最终处理者。

## Frameworks Introduced
- **Chain of Responsibility**：把流程步骤组织成可组合链路。
  - When to use：审批、过滤、校验、拦截器、降级处理。
  - How：统一处理结果 → 显式顺序 → 明确终止条件 → 记录链路轨迹。

## Worked Example
原书把 618 上线审批从多级 `if` 重构为逐级负责人链。每一级只处理自己的权限和状态，再决定是否交给上级。

## Modern Java
过滤器链可返回 sealed 结果，例如 `Continue`、`Handled`、`Rejected`，用穷尽匹配避免含糊的布尔值。异步链必须传播取消、超时和上下文。

## Anti-patterns
- 链顺序由容器偶然决定。
- 节点既修改请求又静默失败。
- 无上限重试或形成环。
- 只有两个稳定步骤仍构建通用流程引擎。

## Key Takeaways
1. 顺序和终止语义属于公开设计。
2. 为每次请求记录经过的节点。
3. 流程复杂到分支、回退和持久化时考虑状态机或工作流引擎。
