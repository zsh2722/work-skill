# Chapter 2: 抽象工厂模式

## Core Idea
创建一组彼此兼容的产品，而不让调用方知道具体产品族。重点不是“更多工厂”，而是保持整套实现的一致性。

## Frameworks Introduced
- **Abstract Factory**：为相关产品族提供统一创建契约。
  - When to use：环境、租户、数据库、云厂商或平台切换时，多种协作者必须成套替换。
  - How：定义产品接口 → 定义家族工厂 → 每个产品族提供完整实现 → 在组合根选择一次。

## Key Concepts
- **产品族**：必须一起工作的相关实现。
- **组合根**：应用启动时完成依赖选择和装配的位置。
- **一致性约束**：防止 A 家族产品与 B 家族产品误配。

## Modern Java
现代应用常由依赖注入容器承担抽象工厂的装配职责。若只需要一个产品，不要为“模式完整”制造产品族；可直接注入接口或使用工厂方法。

## Worked Example
原书以两套 Redis 集群为例：业务仍调用统一缓存接口，适配器吸收方法差异，代理负责选择集群。更现代的实现可在启动配置中选择一套 `CacheFamily`，一次性提供读写、锁和序列化组件。

## Anti-patterns
- 每次业务调用都重新判断产品族。
- 产品族成员不相关，只因“都是对象”而放进同一工厂。
- 让容器定位器遍布业务代码，形成 Service Locator。

## Key Takeaways
1. 抽象工厂保护的是产品族一致性。
2. 产品族在组合根选择，业务内部只依赖接口。
3. 依赖注入可以实现该意图，但不等于随处查容器。
