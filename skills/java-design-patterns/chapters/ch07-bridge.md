# Chapter 7: 桥接模式

## Core Idea
把两个独立变化维度拆成组合关系，避免用继承表示所有笛卡尔积组合。

## Frameworks Introduced
- **Bridge**：抽象维度持有实现维度接口。
  - When to use：渠道×验证方式、设备×渲染器、消息类型×发送通道等两个维度独立扩展。
  - How：找出正交变化轴 → 每轴独立接口 → 在组合根装配。

## Modern Java
若实现维度是单方法、无状态行为，可用函数式接口或方法引用；若存在生命周期和多方法协议，保留显式对象接口。

## Worked Example
原书将微信、支付宝等支付渠道与刷脸、指纹、密码验证拆开。新增渠道无需复制所有验证方式，新增验证方式也无需修改渠道。

## Anti-patterns
- 两个维度实际高度耦合仍强行拆分。
- 用布尔参数假装第二维度。
- 桥接对象同时承担工厂选择和业务执行。

## Key Takeaways
1. 桥接针对两个可独立演进的维度。
2. 组合数开始增长时优先检查继承层次。
3. 装配应发生在边界，不散落在业务流程。
