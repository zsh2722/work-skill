# Chapter 10: 外观模式

## Core Idea
为复杂子系统提供面向用例的粗粒度入口，降低调用方需要理解的协作者数量。

## Frameworks Introduced
- **Facade**：在边界上协调多个底层服务。
  - When to use：调用方必须按固定顺序调用多个组件，或需要隔离易变子系统。
  - How：以用例命名方法 → 在外观中编排 → 保留必要的底层逃生口。

## Worked Example
原书把白名单校验封装成 Spring Boot 中间件，业务接口只声明规则，不重复编写解析、查询和返回逻辑。

## Modern Java
应用服务、模块 API 和 BFF 都可视为外观。外观不是“God Service”：它负责协调，不应吸收所有领域规则。

## Anti-patterns
- 一个外观包含全部系统功能和数百个方法。
- 直接暴露底层 DTO 与异常，使隔离失效。
- 为简单单调用再包一层无语义方法。

## Key Takeaways
1. 外观按业务用例而非技术组件设计。
2. 转换底层错误与模型，形成稳定边界。
3. 外观负责协调，领域对象负责规则。
