# Chapter 9: 装饰器模式

## Core Idea
在保持原接口的前提下，运行时为对象叠加职责；每个装饰器只处理一个横切能力并委托下一层。

## Frameworks Introduced
- **Decorator**：对象包装对象，调用形成可组合管道。
  - When to use：重试、缓存、鉴权、日志、指标、压缩等可选能力。
  - How：共同接口 → 基础实现 → 持有委托的装饰器 → 明确组合顺序。

## Worked Example
原书在 SSO 登录校验外增加方法范围拦截，而不修改原登录服务。类似地，可把日志、计时、重试分别包装在服务外层。

## Modern Java
函数式接口可用高阶函数包装；框架拦截器适合跨大量对象的统一横切逻辑。装饰器顺序是行为的一部分：缓存外层与重试外层会产生不同结果。

## Anti-patterns
- 包装层吞掉异常或改变未声明的语义。
- 装饰器数量过多但没有可观察的调用链。
- 把装饰器与代理当作同义词：装饰器强调加职责，代理强调控制访问。

## Key Takeaways
1. 每层只增加一个清晰职责。
2. 显式测试组合顺序。
3. 对象级组合用装饰器，大范围横切可用 AOP。
