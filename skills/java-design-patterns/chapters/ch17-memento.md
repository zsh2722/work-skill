# Chapter 17: 备忘录模式

## Core Idea
在不暴露对象内部实现的前提下保存可恢复状态，由看护者管理版本历史。

## Frameworks Introduced
- **Memento**：发起者创建和恢复快照，看护者只保存快照。
  - When to use：撤销、配置回滚、编辑历史、游戏存档。
  - How：确定最小快照 → 不可变表示 → 有界历史 → 校验恢复兼容性。

## Modern Java
不可变 record 适合表示快照。数据量大时使用增量事件、数据库版本或事件溯源，不要把完整对象图长期堆在内存。

## Worked Example
原书保存系统配置版本，支持 `undo`、`redo` 和按版本读取。生产实现还应持久化版本、记录操作者，并处理配置 schema 升级。

## Anti-patterns
- 快照包含连接、线程、缓存等不可恢复资源。
- 无界保存每次操作。
- 恢复旧版本时绕过当前不变量校验。

## Key Takeaways
1. 快照应最小、不可变、可版本化。
2. 明确保留期限和存储成本。
3. 事件溯源与备忘录目的相近但不是同一模式。
