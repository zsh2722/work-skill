# Chapter 21: 模板方法模式

## Core Idea
在父类中固定算法骨架，把少量变化步骤留给子类实现，保证所有实现遵守同一执行顺序。

## Frameworks Introduced
- **Template Method**：稳定骨架调用抽象步骤和可选 hook。
  - When to use：流程顺序固定、多个实现只改变少数步骤。
  - How：提取公共步骤 → 定义最小变化点 → 保护骨架不被随意覆盖。

## Worked Example
原书统一登录、抓取、解析和生成海报流程；京东、淘宝、当当实现各自登录与页面解析步骤。

## Modern Java
继承不是唯一方案。若变化步骤可独立组合，可把它们作为函数或策略传入“模板函数”；只有子类与骨架存在稳定 is-a 关系时使用继承。

## Anti-patterns
- 子类覆盖大量 hook，实际改变整个流程。
- 父类依赖子类初始化顺序。
- 为复用两行代码制造深继承树。

## Key Takeaways
1. 模板保护执行标准，变化点应少而清晰。
2. 可组合步骤优先策略和函数参数。
3. 需要修改骨架时重新评估抽象边界。
